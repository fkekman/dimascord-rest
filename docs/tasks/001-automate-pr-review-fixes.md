# 001 — Автоматическое исправление замечаний после ревью PR

Статус: запланировано. Настройка автоматизации ещё не выполнена.

## Цель

После завершения ревью владельцем проекта автоматически запускать Codex для
исправления замечаний в той же ветке pull request. Повторное ревью и слияние
выполняет владелец проекта.

## Согласованный процесс

1. Владелец проекта отправляет ревью через Submit review → Request changes.
2. GitHub Actions обрабатывает событие `pull_request_review` с действием
   `submitted` и состоянием ревью `changes_requested`.
3. Workflow проверяет автора ревью: исправления запускаются только по ревью
   согласованного владельца проекта, а не по комментариям произвольных участников.
4. Отдельный запуск Codex получает актуальный код ветки PR, требования задачи,
   применимые инструкции репозитория и замечания ревью. Текущий чат не является
   источником контекста для этого запуска.
5. Codex исправляет замечания через обязательный TDD: сначала дополняет подходящий
   существующий тест или создаёт новый, проверяет ожидаемое падение, затем меняет
   реализацию и запускает применимые проверки.
6. При успешной проверке workflow публикует исправления в исходную ветку PR
   и отчёт с результатами проверок и статусом замечаний.
7. Если замечание неоднозначно, агент задаёт вопрос в PR и отмечает его как
   требующее уточнения. Слияние и автоматическое одобрение не выполняются.
8. Владелец проекта повторно проверяет изменения и выполняет слияние.

## Область задачи

- Настроить workflow с официальным Codex GitHub Action.
- Настроить API-аутентификацию через GitHub Secrets и права публикации изменений.
- Подготовить окружение для проверок, включая тестовую БД, когда она потребуется.
- Сохранить инструкции запуска в репозитории: область исправлений, обязательный
  TDD, чтение стандартов, обработка неоднозначных замечаний и формат отчёта.
- Учесть, что API-вызовы требуют отдельного бюджета использования OpenAI API.
- Определить поведение при повторных событиях, параллельных запусках и изменении
  ветки PR во время исправлений. Исключить повторную обработку одного ревью
  и перезапись новых пользовательских коммитов.
- Ограничить автоматизацию доверенными PR и авторами. Не передавать секреты
  недоверенному коду PR из внешних форков.

## Критерии приёмки

- Отправка владельцем проекта `Request changes` запускает обработку замечаний.
- Одиночные комментарии, ревью других пользователей, `Approve` и `Comment`
  не запускают исправления.
- Агент получает как текст ревью, так и относящиеся к нему комментарии к коду.
- На демонстрационном PR подтверждён цикл: падающий тест → исправление →
  успешные проверки → коммит в той же ветке → отчёт в PR.
- Если проверки не прошли, результат не объявляется готовым к повторному ревью;
  в PR публикуется причина и результаты проверок.
- Неоднозначные замечания приводят к вопросу в PR, без угадывания требований.
- Повторная доставка события не создаёт дублирующих исправлений.
- Изменение ветки во время запуска обрабатывается без потери чужих коммитов.
- Автоматическое слияние и одобрение отсутствуют.
- Документация описывает настройку секретов, разрешения, запуск и диагностику.
